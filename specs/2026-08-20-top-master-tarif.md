# Топ-мастер по услуге: тариф на сайте, цена и галка в CRM

Дата: 20.08.2026. Источник - постановка Влада (в чат, 20.08.2026):

> У записи должен быть по умолчанию комментарий "откуда пришёл клиент и на каких
> условиях", например "запись к топ мастеру". Когда клиент на сайте выбирает услугу -
> ему открывается выбор: "у обычного мастера за стандартную оплату" или "у топ мастера
> за +". В CRM у владельца есть опция назначить топ-мастера услуги (галка "топ" у услуги
> в карточке сотрудника), и в разделе "Команда" по сотрудникам можно поставить эту галку
> и назначить другую цену услуги.

## Problem

1. Барбершоп продаёт одну и ту же услугу по двум тарифам (обычный мастер / топ-мастер),
   но система об этом не знает: клиент на сайте выбирает мастера вслепую по имени, не
   понимая, чем один дороже другого.
2. Владелец не может пометить, кто топ по конкретной услуге. `master_services.price`
   различие цен уже хранит с Окна 8, но в карточке сотрудника цена **read-only** -
   меняется только длительность (`assets/crm-master-services.js`, поле `.sc-price`
   выводится текстом).
3. Через месяц по карточке записи не понять, на каких условиях клиент записался:
   `staff_comment` (миграция 048) - про расхождение фактической суммы с прайсом,
   `client_source` (миграция 050) - только канал привлечения. Сочетания "откуда + на
   каких условиях" в системе нет.

## Goal

Клиент на сайте осознанно выбирает тариф; владелец управляет тарифом и ценой из карточки
сотрудника; запись хранит условия, на которых она сделана, и показывает их сотруднику
без ручного ввода.

## Scope

- Признак "топ-услуга" на паре (мастер, услуга) - `master_services.is_top`.
- Редактируемая цена услуги мастера в карточке сотрудника (раздел "Команда" у владельца,
  "Сотрудники" у администратора - read-only, как сейчас у остальных полей).
- Публичная воронка записи: услуга → тариф (обычный / топ) → мастер → дата → время.
- Тариф записи (`bookings.master_tier`) фиксируется в момент создания брони и
  показывается строкой условий в карточке записи вместе с источником клиента.

## Acceptance Criteria

1. В карточке сотрудника у каждой услуги есть галка «топ» и поле цены; владелец и
   управляющий их меняют, администратор и мастер видят read-only (тот же уровень
   доступа, что у длительности сегодня).
2. Галка и цена сохраняются общей кнопкой «Сохранить изменения» карточки, переживают F5,
   отправляются только изменённые услуги (текущий контракт `collectServiceChanges`).
3. Цена ≤ 0 / пустая / нечисловая - отказ с подсветкой поля, как у длительности; тихой
   подмены каталожной ценой нет.
4. Галка «топ» доступна только у включённой услуги: снял услугу - галка гаснет вместе с
   полями цены и длительности.
5. На сайте клиент сначала выбирает услуги (каталог с ценой «от»), затем тариф из двух
   карточек: «Обычный мастер - от N ₽» и «Топ-мастер - от M ₽»; карточка тарифа, под
   который нет ни одного доступного мастера, показывается неактивной с причиной, а не
   исчезает молча.
6. После выбора тарифа список мастеров содержит только тех, кто оказывает ВСЕ выбранные
   услуги и подходит под тариф; цена и длительность в сводке считаются по выбранному
   мастеру (как сейчас).
7. Бронь, созданная с сайта или из CRM, получает `master_tier` = `top`, если хотя бы одна
   её услуга помечена у этого мастера как топ, иначе `standard`.
8. В карточке записи (день/клиент) видна строка условий: канал + тариф, например
   «Яндекс Карты · запись к топ-мастеру». Ручной комментарий сотрудника
   (`staff_comment`) остаётся отдельным полем и не затирается.
9. Старые брони (`master_tier IS NULL`) показываются как раньше - без строки тарифа, без
   выдуманного «стандартного».

## Constraints

- Живой прод реального клиента: деплой в оба контура - только по явной команде Влада.
- Порядок шагов формы записи на сайте меняется - это видимое изменение для реальных
  клиентов, предупредить до деплоя.
- Миграция - только schema (правило CLAUDE.md), никаких QA-фикстур.
- Единый компонент карточки услуги, новые токены - в `assets/crm-app-shell.css`, не в
  legacy-монолит `mockup-crm.css`.

## Non-Goals

- Отдельное поле «надбавка за топ» - надбавка выводится из разницы цен мастеров, второго
  источника правды не заводим.
- Онлайн-оплата и предоплата за топ-тариф.
- Автоматическое назначение топ-статуса по выручке/рейтингу - решение владельца, руками.
- Редактирование каталожной цены услуги (`services.price`) из карточки сотрудника.
