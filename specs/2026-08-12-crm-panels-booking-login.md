# Spec: Панели, запись и вход CRM
**Date:** 2026-08-12
**Author:** Владелец проекта Алихан

## Problem
Панели приходится раскрывать по одной, создание записи доступно только через слот календаря, кабинет мастера использует старые пилюли и дублирующую кнопку сообщений, а окно входа визуально отстаёт от утверждённой системы CRM

## Goal
Сделать навигацию по панелям и создание записи прямыми и единообразными во всех кабинетах, не расширяя права ролей

## Scope

### In Scope
- Одно действие для раскрытия и сворачивания всех панелей внутри каждого видимого списка
- Панель «Запись» в расписании только для владельца и администратора
- Переиспользование существующей формы и существующих путей создания/редактирования записи
- Панели «День», «Неделя», «Месяц» вместо пилюль в расписании мастера
- Удаление дублирующей кнопки-конверта у мастера при сохранении рабочего колокольчика
- Приведение окна входа к токенам и визуальным правилам CRM

### Out of Scope
- Изменение API, БД или серверных RBAC-правил
- Добавление мастеру права создавать или переносить записи
- Изменение публичной формы записи
- Деплой

## Acceptance Criteria
- [x] В каждом списке `details.staff-card` есть доступное с клавиатуры действие «Развернуть все», после раскрытия всех панелей оно становится «Свернуть все»
- [x] Действие влияет только на панели своего списка и корректно синхронизируется после ручного открытия или закрытия панели
- [x] Владелец и администратор видят в «Расписании» панель «Запись» и могут открыть через неё существующую форму новой записи без предварительного выбора слота
- [x] Мастер не получает панель «Запись» и по-прежнему не имеет формы создания записи
- [x] У мастера «День», «Неделя», «Месяц» оформлены теми же независимыми панелями, что у владельца, а «Год» не показывается
- [x] В верхней панели мастера остаётся одна кнопка уведомлений, дублирующий конверт удалён
- [x] Окно входа использует фирменную поверхность, золотой rail, общие радиусы, аккуратные поля и не содержит текста о тестовом контуре или доступах Влада
- [x] Desktop и mobile не получают горизонтальный скролл, существующие тесты и новые контракты зелёные

## Constraints
- Существующие ID формы записи и JS-контракты должны сохраниться
- Общий CSS остаётся ограничен `.crm-navigation-ui`
- Внешний вид публичной записи не меняется
- Источник прав - существующий серверный контракт: создавать запись могут owner/admin, master не может

## Non-Goals
- Унификация остальных `seg-bar` в зарплате и аналитике
- Новый тип уведомлений или новая серверная логика сообщений
