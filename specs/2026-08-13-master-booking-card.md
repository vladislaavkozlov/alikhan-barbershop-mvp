# Карточка записи в кабинете мастера - на общую форму (13.08.2026)

## Проблема

В кабинете мастера (`crm-master.html`) клик по записи в календаре открывает старую
карточку-макет `#bd-1`. Владелец и админ с 10.08.2026 (Окно 55) работают с записью в
ОБЩЕЙ форме `#walkinForm` (режим edit), у мастера этот перенос сознательно не делали
("мастер записи не создаёт и не переносит"). Итог сегодня, живьём в коде:

| Элемент старой карточки мастера | Что на самом деле |
|---|---|
| радио "Ожидание / Пришёл / Не пришёл" | **декоративны**: `wireBookingStatusRadios()` выходит по раннему return без `#bk-status-note`, которого у мастера нет |
| кнопка "Клиент не пришёл" | работает (PATCH /bookings/:id/status), но это второй контрол того же статуса рядом с мёртвыми радио |
| "Клиент подтвердил запись" | роута на `bookings.client_confirmed` нет нигде - декорация |
| "Дата рождения клиента 15.08", "Клиент с нами с 03.02.2025", баннер дня рождения | выдуманные литералы в HTML |
| комментарии по клиенту + "Добавить" | `addComment()` в `mockup-crm.js` рисует строку в DOM, никуда не сохраняет |
| "Моя комиссия за запись" | считается по ХАРДКОДУ имён (`MASTER_COMMISSION_PCT['Елизавета']`), а не по реальной ставке из `master_payroll_settings` |
| "Добавить услугу к записи" | работает (PATCH /bookings/:id/services) |

Мастер видит интерфейс, где половина контролов ничего не делает, а два блока показывают
придуманные данные о клиенте.

## Цель

Ни одного контрола, который не сохраняет.

**Итерация 1 (утро 13.08):** мастер работал в той же форме, что владелец и админ, в
границах своих прав (статус + дописать услугу).

**Итерация 2 (вечер 13.08, правки Влада по живому интерфейсу):** мастер запись НЕ
ведёт вообще - состав услуг, фактическую сумму, статус "не пришёл", перенос и удаление
делает администратор. Значит у мастера не форма, а карточка визита на просмотр: когда,
кто, что делаем, сколько это стоит и какая с этого комиссия. Общая форма записи
вернулась к owner/admin без ролевых веток, мастеру - отдельный read-only модуль
`assets/crm-master-booking.js` (~110 строк, ни одного запроса на изменение).

## Что мастеру разрешено бэкендом (проверено по коду, не по памяти)

| Операция | Роут | master |
|---|---|---|
| Сменить статус визита | `PATCH /bookings/:id/status` | **да**, своя запись (`api/routes/bookings.js:498,514`) |
| Дописать услугу | `PATCH /bookings/:id/services` | **да**, своя запись (`:570,585`) |
| Снять услугу (полный состав) | `PUT /bookings/:id/services` | нет - `BOOKING_OPERATOR_ROLES` (`:662`) |
| Перенос / смена мастера | `PATCH /bookings/:id/reschedule` | нет (`:998`) |
| Фактическая сумма + комментарий | `PATCH /bookings/:id/actual-price` | нет (`:1054`) |
| Удалить запись | `DELETE /bookings/:id` | нет (`:412`) |
| Создать запись | `POST /bookings` | нет, явный 403 `master_cannot_create_bookings` (`:367`) |

Телефон клиента мастеру не отдаётся уже на уровне `GET /bookings`.

**Бэкенд в этой задаче не меняется вообще.** Меняется только то, какие контролы мастер
видит и какой роут зовёт кнопка сохранения.

## Scope

1. `crm-master.html`: старая карточка `#bd-1` удалена целиком, вместо неё read-only
   панель `#masterBookingView`. Формы записи (`#walkinForm`) на странице нет вовсе.
2. Панель показывает: время визита, клиента, статус словом, услуги записи списком
   (цена + длительность по прайсу этого мастера), итог, комиссию за запись.
3. Панель НЕ содержит: ни одного input, checkbox или кнопки. Телефон клиента убран
   совсем (вместе с пояснением "скрыто" - лишний шум, номер мастеру и так не приходит).
4. Обёрнута в тот же `details.staff-card`, что "День"/"Неделя"/"Месяц"
   (`upgradeMasterBookingPanel`) - отсюда отступ между карточками, сворачивание и
   участие в "Развернуть все".
5. Статус визита мастер видит, но не ставит: "Ожидание" до визита, "Пришёл" по факту,
   "Не пришёл" - администратор. Кнопка "Клиент не пришёл" ушла вместе с `#bd-1`.
6. Комиссия считается от фактической суммы, если администратор её уже провёл; пока не
   провёл - по прайсу с явной пометкой "предварительно".

## Acceptance criteria

- [x] A1. `#bd-1` и весь его декоративный состав отсутствуют в `crm-master.html`
- [x] A2. Клик по своей записи открывает карточку визита: время, клиент, статус,
      услуги с ценой и длительностью, итог
- [x] A3. В кабинете мастера нет ни одного контрола записи (проверяется живым прогоном
      поимённо, включая поле телефона и радио статуса)
- [x] A4. Карточка визита сворачивается и стоит в одном ряду с "День"/"Неделя"/"Месяц"
      с тем же отступом, что между ними
- [x] A5. Комиссия за запись считается по РЕАЛЬНОЙ ставке мастера
      (`master_payroll_settings`), у владельца-мастера - "не начисляется"; пока
      администратор не провёл фактическую сумму - помечена предварительной
- [x] A6. Владелец и админ не задеты: их форма, перенос, удаление, фактическая сумма
      работают как раньше (регресс-прогон)

## Non-goals

- Не давать мастеру создавать, переносить и удалять записи (решение Влада 08.08.2026,
  подтверждено бэкендом)
- Не заводить новых роутов и миграций
- Не переносить комментарии по клиенту: сохранять их некуда, отдельная задача

## Constraints

- Кастомные виджеты вместо нативных `<input type="date">/<select>` (конвенция проекта)
- Единый компонент карточки/формы, не изобретать вёрстку заново
- Поведение owner/admin не меняется ни в одном сценарии
