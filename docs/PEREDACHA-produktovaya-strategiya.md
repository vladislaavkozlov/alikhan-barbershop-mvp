# Передача контекста: продуктовая стратегия (сессия 01-02.09.2026)

Файл для запуска новой сессии. Прочитать целиком, дальше идти в документы по ссылкам.

## Откуда всё началось

Влад пришёл с болью: он выбрал медицинское направление, опираясь на объём рынка
в 2 трлн, и понял, что это оборот врачей, а не деньги, которые они готовы отдать за
софт. Разбор вывел проблему глубже: дело не в нише, а в модели. Чтобы подключить
одного клиента к CRM, нужно сделать ему сайт, завести арендатора, всё настроить,
отдать в тест - и только потом человек решает, платить ли. Недели работы авансом,
весь риск на исполнителе.

Вывод сессии: продукт остаётся (CRM), меняется способ его продажи - самоподключение.

## Что решено (не пересматривать без причины)

| Решение | Суть |
|---|---|
| **Продукт** | CRM, не радар новостей и не курс. Единственный из вариантов, где каждый следующий месяц легче предыдущего |
| **Продукт не режется** | Продаётся целиком. Короткий вход обеспечивается прогрессивным раскрытием кабинета, а не удалением функций |
| **Не демпинговать** | Цена в одной полке с конкурентом за сопоставимый объём. Выигрывать качеством и маркетингом |
| **Тариф не по объёму использования** | Оси «по числу записей» и «по числу сотрудников» отвергнуты. Платим за доступ к возможностям |
| **Канал бота** | Telegram, не МАКС. МАКС - частный случай Алихана |
| **Оплата** | Только помесячно. К годовой вернуться после первых 10 платящих клиентов |
| **Пробный период** | Не даём. Риск снимается возвратом 14 дней |
| **Открытая цена** | Публикуем полностью - конкуренты годовую сетку не раскрывают. Отстройка, которая ничего не стоит |
| **Бренд** | Личный бренд Влада, `vladkozlovdigital.ru`. Отдельного бренда у продукта нет |
| **Канал привлечения** | Подключается ПОСЛЕ продукта. Решение Влада, риск зафиксирован и перенесён по времени |

## Что открыто и ждёт Влада

1. **Цена.** Влад запросил у Алихана его реальный счёт в YCLIENTS. Известно с его
   слов: 18 000 ₽ в год, плюс 10 000 ₽ в год за двух мастеров = 28 000 ₽ за 4-5
   мастеров = 2 333 ₽/мес, **и это годовая предоплата**. Сравнивать можно только
   одинаковые условия оплаты: их помесячная цена по пропорции ~4 200 ₽. Отдельно
   уточнить, поштучная ли доплата за мастера (5 000 ₽ в год = ~417 ₽/мес за голову).
2. **Структура тарифов.** Влад склоняется к трём (один человек / салон / крупный),
   ссылаясь на маркетинг. Обосновано: эксперимент Дэна Ариели с подпиской The
   Economist из «Predictably Irrational» - третий вариант работает не тем, что его
   покупают, а тем, что делает средний очевидным выбором. Предложено наполнить
   старший тариф **услугами, а не функциями** (настройка под ключ, индивидуальный
   дизайн страницы, приоритетная поддержка, доработки) - тогда его есть чем
   наполнить уже сегодня. В файле пока стоит единый тариф, структура не подтверждена.
3. **Дата для вехи «10 клиентов».** Веха названа, даты нет. Без даты правило выхода
   не работает.
4. **Согласие Алихана и Карины** на кейсы и скриншоты.
5. **Юридический статус.** Отложен решением Влада до «если попрёт». Последствие:
   без статуса нельзя легально принимать регулярную оплату, блок приёма платежей
   не стартует.

## Две фактические ошибки, которые уже исправлены (не повторять)

1. **Мультифилиальности в продукте нет.** Есть мультиарендность - несколько
   независимых заказчиков на одном движке (Алихан, клиника, песочница, RLS, миграции
   057-060). Несколько точек у одного заказчика - отсутствует: таблица `locations` и
   поля `location_id` есть с миграции 002, но роут точек работает лишь справочником в
   редакторе сотрудника, виджет записи о филиалах не знает, выбора точки при записи
   нет. Сегмент сетей и франшиз закрыт до появления этой функции.
2. **Преимущество, оплаченное недополученной выручкой, - это скидка.** «Сообщения
   без счёта» и «цена не зависит от числа сотрудников» - скидки, а не преимущества.
   Настоящие: кнопки в напоминании, отчёт по недополученной прибыли, открытая цена,
   скорость доработок, прямой контакт с автором.

## Известный пробел, который надо закрыть

**Персональные данные и 152-ФЗ.** В системе обрабатываются медицинские данные
пациентов клиники - это специальная категория с отдельными требованиями: согласия,
уведомление регулятора, место хранения базы, договор поручения обработки. Для двух
заказчиков риск терпимый, для продукта на подписке - нет. В документах продукта эта
тема не отражена вовсе. Влад согласия на добавление раздела пока не давал.
