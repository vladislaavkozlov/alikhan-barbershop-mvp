# barbershop-alikhan-mvp - карта проекта

## PRODUCT

CRM + публичный сайт записи для барбершопа "Алихан" (Ставрополь, 2 точки). Реальный клиент, реальные деньги, прод. Разработка идёт скиллом `вайбкодинг` через пронумерованные "окна" (один промпт = одна фича/фикс). Реестр всех окон - `WINDOWS-INDEX.md`, не пересказывается сюда. Последнее сделанное - `git log` и первые строки `WINDOWS-INDEX.md`, не хранится в этом файле.

## BUSINESS RULES

- **Деплой - два независимых контура.** GitHub Pages (фронтенд) - обычный `git push origin main`. Amvera (бэкенд) - ОТДЕЛЬНЫЙ плоский репозиторий (`git.msk0.amvera.ru/vladislaavkozlov/alikhancrm1`), своя история, деплой = копирование `server.mjs`+`lib/`+`routes/`+`migrations/` в клон и пуш в `master`. Гочи - память `reference_amvera-deploy-gotchas.md`
- **Деплой в любой контур - только по явной команде.** Код готов локально после окна ≠ разрешение задеплоить

## CRITICAL RULES

- **`assets/mockup-crm.js`** - classic `<script>` (не ES-модуль), держит виджеты даты/времени и `updateNoShowUi()` через `onclick=` (ограничение браузера - `onclick` резолвится только через глобальный `window`). Осознанно не мигрирован при декомпозиции `crm-auth.js`. Не трогать попутно с другими задачами
- **`assets/mockup-crm.css`** (~1000 строк, legacy) - новые design tokens редизайна владельца идут в `assets/crm-app-shell.css`, не в этот монолит
- **`assets/crm-schedule-views.js`** (~760 строк) - крупнейший фронтенд-файл, кандидат №1 на декомпозицию тем же методом, что `crm-auth.js` (образец - `plans/archive/`)
- **Миграции - только про schema** (таблицы/колонки/индексы/constraints), никогда про временные QA-фикстуры конкретного окна. Инцидент 04.08.2026: такая миграция (`DELETE FROM staff` на непредусмотренном FK) уронила прод на ~20 минут - упавшая миграция валит весь сервер, не только новый роут. QA-фикстуры - внутри `tools/verify-*.mjs` через прямые SQL/API-вызовы на эфемерной тестовой базе
- **Выбор даты/времени/длинного списка** - свой темизированный виджет, не нативный `<input type="date">`/`<select>`
- **Любой блок внутри раздела owner-CRM** - единый компонент карточки `details.staff-card` + `.avatar-icon`, не изобретать вёрстку заново
- **security-review** - перед каждым коммитом с новым пользовательским вводом
- **Поведение/API-контракты при структурном рефакторинге не меняются** - код переносится, не переписывается

## COMMANDS

- Офлайн-тесты: `node --test` из корня проекта (НЕ передавать директорию аргументом - падает в песочнице; node сам находит `*.test.js` по конвенции)
- Бэкенд локально: `cd api && npm start` (эквивалент `node server.mjs`)
- Фронтенд - статика без сборки, локальный сервер на порту 8793 (пример - любой из `tools/*.mjs`)
- Живой CDP-прогон конкретного окна: `node tools/verify-<окно>.mjs`

## WORKFLOW

- Декомпозиция большого файла - по одному домену за раз, отдельный коммит на каждый, `node --check` + офлайн-тесты + живой CDP после каждой фазы
- Честная поправка к ТЗ лучше, чем выдуманная реализация - если промпт разошёлся с реальным кодом, фиксировать поправку явно, не подгонять факт под текст
- Новая задача - через скилл `вайбкодинг`, с объявлением размера (S/M/L) в начале
