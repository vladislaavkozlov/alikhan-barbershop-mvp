# Волна 1: сообщения клиенту через МАКС

Дата: 01.09.2026 · Статус: план, реализация не начата
Заказчик уточнил: канал - мессенджер МАКС (у Алихана есть MAX Бизнес), не Telegram

## Что меняется относительно исходного плана Волны 1

Состав сообщений, тайминги и эффект остаются те же. Меняется транспорт и добавляется
одна новая задача, которой не было в телеграм-версии: привязка клиента к боту.

Главное ограничение платформы: бот МАКС не может написать пользователю первым.
`chat_id` появляется только когда человек сам открыл бота (событие `bot_started`).
Значит без шага привязки ни подтверждение, ни напоминание, ни просьба об отзыве
не доедут. Это не деталь реализации, а изменение сценария записи на сайте.

## Архитектура: движок отдельно, канал отдельно

- `notifications_outbox` - что отправить, кому, когда, по какому поводу, статус доставки
- `client_channels` - (tenant_id, client_id, channel, external_id, subscribed_at)
  channel = max | sms; external_id для МАКС = chat_id
- транспорты: `lib/channel-max.js`, `lib/channel-sms.js`, выбор канала - по наличию
  строки в client_channels, fallback на SMS
- планировщик: тик раз в минуту, берёт due-записи из outbox, шлёт, пишет результат

Отдельные транспорты нужны не ради красоты: SMS платная и поштучная, МАКС бесплатный,
а следующему арендатору может понадобиться другой канал.

## Привязка клиента (новый шаг)

1. Клиент оформил запись на сайте
2. Экран «Запись создана» показывает кнопку «Подтверждение в МАКС» с deep link
   `https://max.ru/<ник_бота>?start=<payload>`, payload до 128 символов -
   кладём одноразовый токен привязки, не телефон и не id брони в открытую.
   Ник выбрать нельзя, он генерируется как `idИНН_bot` (у самозанятого `se(orgid)_bot`),
   поэтому ссылка нечитаемая: полагаемся на кнопку и QR-код, устно её не диктуем
3. Клиент открыл бота, приходит `bot_started` с payload и chat_id
4. Сервер сверяет токен, пишет строку в `client_channels`, бот сразу отвечает
   подтверждением записи с кнопками
5. Кто не привязался - уходит в SMS

Ту же кнопку показываем в SMS-подтверждении («подключи МАКС, дальше бесплатно»)
и на карточке клиента в CRM, чтобы админ мог отправить ссылку вручную.

## Сообщения и кнопки

- сразу после записи: подтверждение, кнопки `callback` «Приду / Перенести / Отменить»
- за сутки и за два часа: напоминание, те же кнопки
- «Приду» → `client_confirmed = true` (колонка есть с 002_schema.sql, роута нет),
  плашка в расписании красится
- «Перенести / Отменить» → уведомление администратору в CRM, ручная обработка в первой версии
- через 2 часа после визита: просьба об отзыве, кнопки типа `link` на 2ГИС и Яндекс.Карты,
  триггер - `review_request_pending`, который уже проставляется в bookings.js:745

## Техника МАКС

- база API: `https://platform-api2.max.ru`, авторизация токеном, лимит 30 rps
- продакшн - webhook: `POST /subscriptions` с нашим HTTPS-адресом на Amvera,
  long polling только для локальной отладки, одновременно нельзя
- события подписки: `bot_started`, `message_created`, `message_callback`
- кнопки только inline, типы: callback, link, request_contact, open_app и другие

## Риски

- модерация до 48 часов рабочих, до неё проверить отправку нельзя
- имя, аватар, описание и приветствие меняются только в кабинете организации Алихана
  и каждое сохранение уходит на повторную модерацию; тексты сообщений, кнопки и
  логика - наш код и от кабинета не зависят вообще
- бот МАКС доступен только юрлицам, ИП и самозанятым - у Алихана должен быть подходящий статус
- deep link работает на iOS 2.7.0+ и Android 2.9.0+, на старых клиентах кнопка не сработает,
  для них остаётся SMS
- доля привязавшихся - главная неизвестная всей волны: если привяжется 30%,
  экономия на неявках будет втрое меньше расчётной, а SMS-счёт втрое больше
