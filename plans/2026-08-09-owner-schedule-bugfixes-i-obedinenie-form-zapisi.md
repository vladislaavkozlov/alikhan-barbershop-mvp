## Часть 2 - объединение форм записи (крупная фича, отдельный контракт)

Текущее архитектурное понимание (проверено по коду):
- Старая форма (`openBooking()`/`#bd-1`, `mockup-crm.js`) - только просмотр + статус, поля
  Клиент/Телефон/Мастер/Услуга/Время всегда `readonly`, редактировать существующую запись
  сейчас нельзя вообще
- Новая форма (`crm-walkin.js`) - интерактивная, стилизованные виджеты, уже поддерживает 3
  режима с разным заголовком ("Новая запись на выбранное время"/"Повторная запись"/"Новая
  запись без предзаписи") - добавить 4-й режим "редактирование существующей" технически
  расширяет уже готовый паттерн

**Ответы Влада получены 09.08.2026:**
1. "Др. клиента" = сначала ИДЕНТИФИЦИРОВАТЬ клиента (по телефону), понять - есть он уже в базе
   или нет, потом либо подтянуть его данные, либо завести нового. Не бинарный выбор "другой
   существующий vs новый" - единый флоу "определить, потом решить".
2. Да, разрешаем менять мастера/время/услугу у уже существующей записи.

**Находка при проверке бэкенда (меняет объём):**
- Клиент уже неявно создаётся/находится при СОХРАНЕНИИ любой брони - `INSERT INTO clients ...
  ON CONFLICT (phone) DO UPDATE` (`api/routes/bookings.js:106-107`). Явного поиска "уже есть или
  нет" ДО заполнения формы не существует - нужен новый бэкенд-контракт (поиск по телефону).
- Смена УСЛУГИ у существующей записи уже поддержана (`PATCH /bookings/:id/services`). Смена
  МАСТЕРА и смена ДАТЫ/ВРЕМЕНИ у существующей записи - **не поддержаны бэкендом вообще**, такого
  эндпоинта нет. Это не только объединение форм на фронте, это ещё один новый контракт с той же
  проверкой доступности, что у создания записи (только исключая текущий слот самой записи из
  проверки конфликта).

**Разбито на два окна (Shared-Contract-First - контракт до потребителя):**
- Окно 54 - бэкенд-контракт: поиск клиента по телефону + перенос записи (мастер/дата/время)
- Окно 55 - фронт: слияние форм в `crm-walkin.js` (4-й режим "редактирование") + идентификация
  клиента по телефону в UI + удаление старой формы `#bd-1`/`openBooking()`, только после того как
  Окно 54 подтверждено живьём
