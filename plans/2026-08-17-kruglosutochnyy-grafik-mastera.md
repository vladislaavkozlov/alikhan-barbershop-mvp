# Круглосуточный график мастера (00:00-23:59) - 17.08.2026

Размер: M. Одна общая шкала времени + опции пикера, но потребителей несколько:
график в «Команде», календарь «День» в 3 ролях, форма записи CRM, публичный виджет.

## Задача (Влад, 17.08.2026)

> В «Команде» дать возможность поставить мастеру график с любого времени по любое
> (00:00-23:59), а не 10:00-20:00 как сейчас. Время записи к сотрудникам должно
> учитываться и работать по этому графику и в CRM, и на сайте.

Не ограничивало (проверено, не трогаем):
- БД: `master_weekly_schedule` (миграция 022) без CHECK на часы
- `getEffectiveSchedule` / `fullDayOffWindow` / `hasAvailableSlot` уже считают от
  реального окна мастера, глобальный дефолт 10:00-20:00 остаётся фолбэком «графика нет»
- публичный виджет: `storage.js getEffectiveWindowFor` берёт окно из `GET /schedule`,
  слоты строятся от него - расширится сам
- Неделя/Месяц/Год: показывают часы текстом, геометрии часов не имеют

## Границы

- Смена через полночь (20:00-04:00) не поддерживается: смена привязана к одной дате
  (`schedule_shifts.date`, start < end). «Круглосуточно» = 00:00-23:59 внутри суток
- Глобальный дефолт 10:00-20:00 для мастера без графика не меняется

## Уточнение Влада после первого показа (17.08.2026)

> «в графике эти часы нужно ставить только, если у сотрудника есть рабочие часы в это время»

Шкалу дня раздвигает ТОЛЬКО график мастеров. Записи на неё не влияют (первая версия
расширяла окно и по броням). Чтобы запись, время которой разошлось с графиком, не
пропала молча, её карточка прижимается к краю трека и помечается `.appt--outside`
(пунктирная рамка + «⚠ вне графика»). Через API такую запись создать нельзя - сервер
сам отклоняет время вне смены (`createBookingTx`, `schedule_blocked`), проверено живьём;
страховка нужна для состояния «запись создана раньше, график изменили потом».

## Второе уточнение Влада, вечер того же дня (по живому проду)

> «в чём здесь конкретно ошибка? Что перерыв вне рабочего дня? - тогда так и нужно
> написать в ошибке в конкретном случае» + «перерыв если ставить, например с 5:15 до
> 5:15 тоже такая же ошибка возникает»

Одна общая фраза «проверьте время» заменена на конкретную причину с днём недели и
часами. Проверка живёт в форме (`firstWeeklyProblem`, `assets/crm-schedule-editor.js`) -
ответ мгновенный, до запроса; сервер отдаёт ту же причину кодом (`analyzeWeeklyChanges`:
`work_end_before_start` / `break_end_before_start` / `break_outside_work` /
`missing_work_time` / `missing_break_time`) в поле `error`, для заявки мастера и любого
другого клиента. Второй, общий тост от кнопки «Сохранить изменения» убран (`reported`).
Прогон: `tools/verify-2026-08-17-oshibka-grafika-konkretno.mjs` 13/13.

## Найдено по ходу (не было в исходном разборе)

- [x] **`storage.js getEffectiveWindowFor` падал на любом мастере вне жёсткого списка
  `MASTERS` (master-1/2/3)** - `findMaster` бросает «Неизвестный masterId», а
  `app.js refreshSlots` ловит это в общий catch и пишет клиенту «Не удалось загрузить
  свободное время - проверьте подключение». То есть у мастера, созданного через
  интерфейс CRM (`staff-<hex>`), публичный сайт не показывал свободное время ВООБЩЕ -
  независимо от круглосуточного графика. Найдено живым прогоном. Фикс: справочник
  `MASTERS` больше не обязателен, фолбэк - общие часы салона (`SHOP_DEFAULT_WINDOW`),
  реальные часы всё равно приходят из `GET /schedule`. Тесты
  `tests/storage.free-slots-window.test.js`
- [x] **Нерабочие часы мастера на суточной шкале выглядели рабочими** - найдено
  снимком экрана: пока шкала совпадала с окном салона, часов вне смены в колонке не
  существовало; на общей шкале 00:00-24:00 колонка мастера с 10:00-20:00 читалась как
  рабочая круглые сутки. Фикс: `.appt--offhours` - тихая штриховка вне смены
  (`buildOffHoursCards`), в обычном дне блоков нет вовсе
