Спека: `specs/2026-08-24-multitenancy-etap-b-slovar.md` · Размер: L · Дата: 24.08.2026
Окно: `брифы/ПРОМПТ-ОКНО-68-ETAP-B-SLOVAR-VERTIKALI.md`
Статус: **гейт пройден 24.08.2026, фазы 1-7 к исполнению**

## Что уже решено и не переспрашивается

### Ответы Влада на гейте 24.08.2026

- **Слова клиники - работаем по черновику окна** (мастер→врач, запись→приём,
  услуга→процедура, клиент→пациент, салон→клиника). В файле словаря стоит явная
  пометка «не согласовано с Кариной». Правка после её ответа - один диф в одном файле
- **Флаги модулей - два**: `missedProfit` (недополученная прибыль и возврат ушедших)
  и `payroll` (зарплата и ставки мастеров). Витрина мастеров и запись с улицы
  флагами НЕ становятся, хотя окно называло витрину отправной точкой - это осознанный
  выбор Влада, а не пропуск. Механизм рассчитан так, что третий флаг добавляется одной
  строкой в списке, без правок в кабинетах
- **Механизм - вариант A** (формы существительных плюс фразы-исключения)

### Из Этапа A

- Полномочия ролей общие для всех арендаторов (решение Влада 24.08.2026)
- Запуск Карины идёт на текущем функционале, орто-модули - Этап D
- Арендатор Карины в этом окне не заводится
- Деплой - только по явной команде Влада

## Challenge Log

### Q1. Решает ли это проблему?

Каждый критерий приёмки спеки закрыт фазой:

| Критерий | Фаза |
|---|---|
| 1. Слова в одном месте (греп-тест) | Ф1 (тест) + Ф3-Ф6 (вычистка) |
| 2. Один экран, разные слова | Ф1 (контракт) + Ф7 (живой прогон) |
| 3. На экране клиники нет барбершопных слов | Ф2 (скринер) + Ф7 |
| 4. У Алихана ничего не изменилось | Ф7 |
| 5. Незнакомая вертикаль не ломает экран | Ф1 |
| 6. Словарь недоступен - кабинет жив | Ф2 |
| 7. Флаг режет на сервере, а не в меню | Ф6 |
| 8. Новая вертикаль = один файл плюс строка | Ф1 |
| 9. Формы полны | Ф1 |

### Q2. Самое ли эффективное решение? Четыре варианта

| | Подход | Плюсы | Минусы | Вердикт |
|---|---|---|---|---|
| **A** | Формы существительных плюс отдельный список фраз-исключений, где рядом согласуемое слово | Словарь вертикали - ~50 строк, а не 450. Новая вертикаль пишется за час. Род и падеж под контролем | Нужен список фраз-исключений, его надо не пропустить. Лечится скринером стоп-листа (критерий 3) | **выбран** |
| **B** | Полный пофразовый словарь на весь интерфейс (классический i18n, ключ → строка на вертикаль) | Индустриальный стандарт, ноль морфологии, ошибка падежа физически невозможна | ~450 ключей руками. Правка одной надписи требует правки во всех вертикалях. Диффом задевается каждая строка трёх боевых кабинетов - худший риск для живого прода Алихана | отклонён как основной, но именно так делаются фразы-исключения внутри A |
| **C** | Подстановка регуляркой по готовому DOM после отрисовки | Дёшево, кабинеты не трогаются | Ломает поле ввода и то, что человек сам напечатал. Не знает падежей. Мигает барбершопным словом перед заменой. Слова остаются размазанными по коду - цель окна не достигнута | отклонён |
| **D** | Форк файлов фронта на каждого клиента | Быстро на первом клиенте | Два кабинета расходятся на первой же правке. Это ровно инцидент 13.08.2026, только в масштабе всего интерфейса | отклонён |

**Библиотеки склонения** (`petrovich`, `lvovich`, `numeral-russian`) рассмотрены и
отклонены: у API нет внешних зависимостей кроме `pg` (ограничение спеки Этапа A), а
склонять нужно пять слов, а не открытый список. Ручной словарь честнее автомата,
который на слове «приём» даст «приёма» и «приёмов» правильно, а на редком термине
клиники ошибётся молча

**Где живёт истина.** Источник - `api/lib/vertical-terms.js`, потому что на Amvera
уезжают только `server.mjs` + `lib/` + `routes/` + `migrations/`, а фронт живёт на
чужом домене отдельным контуром. Второй копии словаря во фронте нет: он забирает
словарь роутом `GET /tenant/appearance` по домену запроса. Это и даёт критерий 8

### Q3. Есть ли код ради кода?

- Английский и второй язык не заводим: вертикаль это не локаль, язык один
- Редактор словаря в интерфейсе не делаем: слова правит разработчик деплоем
- Слова в базу не кладём: их нельзя протестировать и нельзя откатить вместе с кодом.
  В базе живут только флаги модулей - там значение и правда своё на арендатора
- Публичный лендинг `index.html` не трогаем: у Карины свой сайт
- Комментарии в коде не переводим: их видит разработчик, а не врач

### Q4. Есть ли общий контракт, от которого зависят несколько потребителей?

Да, и это главный риск окна: словарь читают три кабинета и серверные уведомления.
По дисциплине «контракт раньше потребителей» контракт (Ф1) и слой применения (Ф2)
идут отдельными фазами и должны быть зелёными до того, как откроется первая фаза
кабинета. Кабинеты переводятся по одному (Ф3, Ф4, Ф5), а не пачкой -
post-mortem 03.08.2026 (Окно 16) стоил дорого именно на этом

## Устройство словаря

```js
// api/lib/vertical-terms.js - единственный источник слов
export const TERMS = {
  barbershop: {
    master: { g: 'm', nom: 'мастер', gen: 'мастера', dat: 'мастеру', acc: 'мастера',
              ins: 'мастером', pre: 'мастере', nomPl: 'мастера', genPl: 'мастеров', ... },
    booking: { g: 'f', nom: 'запись', ... },
    service: { g: 'f', nom: 'услуга', ... },
    client:  { g: 'm', nom: 'клиент', ... },
    place:   { g: 'm', nom: 'салон', ... },
  },
  clinic: { ... },   // слова ждут подтверждения Влада, черновик помечен в файле
};

// Фразы, где рядом стоит согласуемое слово - выводить правилом нельзя
export const PHRASES = {
  barbershop: { 'booking.new': 'Новая запись', 'booking.cancelled': 'Запись отменена', ... },
  clinic:     { 'booking.new': 'Новый приём',  'booking.cancelled': 'Приём отменён',  ... },
};
```

Неизвестная вертикаль и недостающий ключ падают в `barbershop` - это критерий 5

## Фазы

### Фаза 1. Контракт словаря и флагов (ветка `feature/vertical-terms`)

Фронтенд не трогается.

- `api/lib/vertical-terms.js` - термины, формы, род, фразы, `termsFor(vertical)` с
  откатом в `barbershop`
- `api/lib/vertical-modules.js` - состав флагов и значения по умолчанию на вертикаль
- Миграция `060_tenant_modules.sql` - колонка `tenants.modules jsonb NOT NULL
  DEFAULT '{}'`. Только схема, значения Алихана не трогаются: пустой объект означает
  «как по умолчанию для вертикали»
- `api/lib/tenants.js` - `modules` читается вместе с остальными полями арендатора,
  кэш на минуту уже есть
- Публичный роут `GET /tenant/appearance` - `{ vertical, terms, phrases, modules }`
  по домену запроса. До входа в систему, потому что словарь нужен экрану входа
- Серверный `t(key, form)` для заголовков уведомлений

**Тесты (сначала красные):** откат неизвестной вертикали в барбершоп; полнота форм
по всем вертикалям и всем ключам, которые реально используются; эффективные флаги =
умолчание вертикали плюс переопределение арендатора; роут отдаёт словарь по домену
и 404 на неизвестном домене; словарь не протекает между арендаторами на одном
соединении. **Мутация:** подменить вертикаль в справочнике - тест обязан упасть

**Живой прогон:** `tools/verify-2026-08-25-vertical-terms.mjs` на настоящем
Postgres, два арендатора с разными вертикалями

**Гейт:** `node --check`, полный `node --test` зелёный (655 плюс новые)

### Фаза 2. Слой применения во фронте (ветка `feature/vertical-terms-front`)

Экраны ещё не переводятся - только механизм.

- `assets/crm-terms.js` - забирает словарь при старте параллельно с `/auth/me`,
  `T('master.nomPl')`, `P('booking.new')`, применение к разметке по `data-term`
- Откат: запрос упал, пришёл битый или пустой - остаётся барбершопный текст,
  который уже написан в HTML. Это и есть значение по умолчанию, критерий 6
- Мигания не будет: `main` и так скрыт до входа, словарь приходит раньше отрисовки
- `tools/scan-vertical-leftovers.mjs` - скринер: поднимает кабинет под вертикалью
  `clinic`, собирает весь видимый текст через CDP и падает на стоп-листе
  `мастер|запис|услуг|клиент|салон|стрижк|барбершоп`
- Греп-тест исходников: барбершопное слово вне комментария допускается только на
  строке, где стоит `data-term` или вызов `T(`/`P(` - то есть как явный откат

**Тесты (сначала красные):** `T` без загруженного словаря отдаёт барбершопное слово;
битый ответ не роняет кабинет; `data-term` подставляет форму; неизвестный ключ
отдаёт барбершопное значение, а не пустоту

**Гейт:** оба скринера гоняются на кабинете владельца и честно красные - на этой
фазе экраны ещё не переведены, красный ожидаем и записывается как база отсчёта

### Перекройка фаз 3-5 (24.08.2026, по факту разбора файлов)

План делил работу по кабинетам. Разбор показал, что так не делится: форма записи,
календарь, статусы визита, уведомления и всплывающие сообщения - ОДНИ И ТЕ ЖЕ модули
во всех трёх кабинетах. Переводить их «в фазе владельца» значило бы молча менять
экраны администратора и мастера. Поэтому общие модули стали своей фазой, идущей
раньше кабинетов - тот же принцип «общее раньше потребителей», что и у контракта.

Заодно уточнился объём: **225 строк видимого текста в 28 файлах**, а не 424. Первый
грубый замер считал продолжения HTML-комментариев и строки импортов - в кабинете
владельца из 107 «строк» настоящих оказалось 28.

**Гейт:** скринер под `clinic` зелёный по кабинету владельца; CDP-прогон под

### Фаза 5. Кабинет администратора (ветка `feature/vertical-admin`)

### Фаза 6. Кабинет мастера (ветка `feature/vertical-master`)

### Фаза 7. Серверные тексты и флаги модулей (ветка `feature/vertical-modules`)

- 16 мест в `api/routes/bookings.js`, `clients.js`, `analytics.js` переводятся на `t()`
- Флаг режет раздел на сервере: роут выключенного модуля отвечает отказом, а не
  отдаёт данные. Список роутов на флаг живёт рядом со списком флагов, одним местом
- Меню кабинетов (`assets/crm-app-shell.js`) скрывает выключенный раздел

**Тесты:** выключенный модуль → отказ по прямому запросу к API, а не только
скрытый пункт меню. **Мутация:** снять проверку в роуте - тест обязан упасть

### Фаза 8. Живой прогон, регресс, отчёт

- `tools/verify-2026-08-24-tenant-cabinets.mjs` расширяется вторым арендатором:
  один и тот же кабинет под двумя вертикалями, слова разные
- Прогон под `barbershop`: ни одного «врача» на экране, у Алихана всё как было
- Полный офлайн-набор: 655 плюс новые, ни одного упавшего
- `/security-review` и самопроверка: словарь публичен по домену - убедиться, что
  через `GET /tenant/appearance` не утекает ничего, кроме названия и слов

## Порядок и параллельность

Ф1 → Ф2 → Ф3 (общие модули) → Ф4 → Ф5 → Ф6 (кабинеты по одному) → Ф7 → Ф8.
Параллельно не запускается ничего: каждая фаза правит общий словарь фраз, и
разошедшийся словарь - тот же класс ошибки, ради которого затевалось окно

роуту словаря, а предмет той защиты - обёртка в контекст, а не число аргументов);
список `DETACHED_ROUTES` оставлен ТОЧНЫМ и просто обновлён - ослаблять его нельзя,
он не пускает сюда роут, который что-то пишет

### Прогон кабинетов был сломан - три первопричины найдены и устранены

Сначала я списал плавающие результаты на «дефекты, существовавшие до окна» и обошёл
их заплатками. Влад потребовал искать корень - и правильно: **две из трёх «находок»
оказались моими неверными выводами, а не дефектами продукта**.

1. **Кнопка «Развернуть все» выбиралась не та.** Кнопок на странице несколько - своя у
   каждого раздела, и все `position:fixed` в одном углу. Прогон искал первую по тексту,
   а `innerText` скрытого элемента в Chrome всё равно возвращает текст. Попадалась то
   видимая, то нет; при неудаче хит-тест не подтверждал попадание, и прогон **молча**
   шёл дальше, сверяя вдвое более бедный экран - отсюда «то 2716 знаков, то 789».
   Проверка `offsetParent` тут тоже врёт: у `position:fixed` он всегда `null`.
   Теперь выбирается кнопка с ненулевым размером, хит-тест сохранён, а результат
   подтверждается сменой `aria-expanded`, а не попаданием курсора
2. **Драйвер печатал не по-человечески.** `typeReal` слал текст прямо в `keyDown`.
   Chrome вставляет символ по отдельному событию `char`, поэтому текст доходил через
   раз: поля входа на втором и третьем кабинете оставались пустыми, сервер отвечал
   «Введите email и PIN». Канонический порядок - `keyDown` без текста, `char` с
   текстом, `keyUp`. Оставить оба (текст в `keyDown` И `char`) нельзя: символ
   задваивается, «1234» превращается в «11223344» - проверено стендом на четырёх
   образцах, включая кириллицу
3. **Клик по координатам через CDP доставляется нестабильно** - это единственное, чему
   я первопричину не нашёл. На одной странице сессии клик проходит, на другой не
   доходит ни одно событие мыши, при том что элемент в этой точке верхний, страница
   видима и в фокусе. Проверено: дело не в размере окна, не в эмуляции вьюпорта, не в
   прогреве ввода, не в оставшихся процессах Chrome и не в задержке. Решение по сути:
   хит-тест (ради которого координатный клик и заводился 09.08.2026) оставлен, а само
   нажатие идёт по элементу - координатный клик добавлял ложные падения, не добавляя
   проверки. Ограничение записано в `tools/cdp.mjs`

**Что из этого следует про мои прежние выводы.** «Кабинеты администратора и мастера
пустые - 166 и 134 знака» было НЕВЕРНО: пустыми они выглядели из-за сломанного ввода.
С исправленным прогоном администратор даёт 2448 знаков, мастер - 1192, оба проходят
пять прогонов из пяти. Отдельное окно под это не нужно

**Скринер тоже стал видеть весь экран** - и сразу нашёл мою ошибку: панель «Запись»
строится до прихода словаря и оставалась барбершопной. Помечена `data-term` /
`data-phrase`, теперь подстановка догоняет её. **Скринер: 22 → 9 слов**

### Фаза 4 - выполнена 24.08.2026, ветка `feature/vertical-owner`

Кабинет владельца и его модули: команда, клиенты, аналитика, недополученная прибыль,
тревоги расписания. **Сито №1: 115 → 35 строк** (осталось два файла - кабинеты
администратора и мастера). **Скринер: у владельца под клиникой ноль барбершопных
слов**, всего на трёх экранах 6

  запасной вариант, если словарь не загрузился

  читает краулер до выполнения скриптов) и «учётная запись» (это аккаунт, а не визит).

**Регресс, пойманный сверкой экранов, а не тестами.** Переведя таблицы подписей в
функции, я не поправил три обращения к ним - раздел «Команда» у владельца и
администратора падал с «roleLabel is not defined». Офлайн-набор этого не видел.

используется как объект, и словарь нигде не зовётся на верхнем уровне модуля

**Прогон кабинетов: третья попытка, теперь честная.** Клавиатурный ввод драйвера снова
перестал доходить до второй страницы - значит `char` в прошлый раз совпал, а не
вылечил. Разобрано и отброшено: перезагрузка страницы (проверено маркером в `window`),
чужая сессия в `localStorage`, вторая вкладка браузера, размер окна, эмуляция
вьюпорта, прогрев ввода, занятость главного потока. Первопричина не найдена, и это
записано как есть. Вместо тихого промаха `typeReal` теперь **проверяет результат и
падает громко** - молчаливый промах уже стоил ложного вывода «кабинеты пустые». Вход в
многокабинетных прогонах идёт через `type()`
