# План: источник клиента + карточка записи в «Дне» (17.08.2026)

Размер: M. Задача Влада (17.08.2026, два сообщения):
1. В карточке записи вида «День» показывать имя клиента + телефон (кому положено по
   правам) + «откуда пришёл клиент» (Яндекс Карты / 2ГИС). Метка «+1 новый клиент» -
   только если клиент новый; уже обслуживался - источник не показывать.
2. Запись на 15 минут физически не вмещает эти строки - нужна опция раскрыть карточку
   прямо в «Дне», по аналогии с раскрытием самих карточек-вкладок расписания
   (`details.schedule-view-card`).

## Что уже есть (проверено в коде, не предположение)

- Имя и телефон уже приходят на карточку (`data-client`/`data-phone`,
  `assets/crm-calendar.js` buildApptCard). Права разведены на сервере:
  `clientPhone` отдаётся только `BOOKING_OPERATOR_ROLES` (owner/manager/admin),
  мастеру - нет (`api/routes/bookings.js`, listBookingsForRequest)
- Признака «новый клиент» нет ни в схеме, ни в контракте
- Поля «откуда пришёл клиент» нет вообще. Существующий `staff_comment` (миграция 048) -
  про другое (почему фактическая сумма отличается от прайса) и заполняется только в
  режиме редактирования. Его НЕ переиспользуем: свободный текст не даёт считать каналы
- Компактный режим карточки (`appt--compact`, длительность < 32 мин) прячет строку `.c`
  и показывает её на `:hover` - на телефоне hover'а нет, то есть сейчас у короткой
  записи вообще нет способа увидеть содержимое, кроме открытия формы

## Решение (Challenge Loop)

**1. Решает ли задачу?** Да: отдельная колонка `bookings.client_source` + автоопределение
на публичном сайте + ручной ввод в CRM закрывают «откуда пришёл», вычисляемый
`clientIsNew` закрывает «+1 новый клиент», раскрытие карточки закрывает 15-минутную запись.

**2. Альтернативы:**
- *Свободный текст в существующий `staff_comment`* - дешевле на одну миграцию, но
  «2гис», «2 гис», «карты» в одной колонке не суммируются, аналитику каналов не собрать.
  Отклонено: Влад просил именно источник, а источник без счёта каналов бесполезен
- *Спрашивать клиента на сайте («Откуда вы о нас узнали?»)* - точнее для тех, кто ответит,
  но это лишний шаг в живой форме записи на боевом сайте и падение конверсии ради поля,
  которое в 80% случаев определяется автоматически. Отклонено, публичную форму не трогаем
- *Хранить источник на клиенте (`clients.source`)* - не подходит для walk-in без телефона
  (у них `client_id` = null по решению Алихана, миграция 041), источник потерялся бы.
  Держим на брони

**3. Code for code's sake?** Нет: каждый пункт - буквальный пункт задачи. Декомпозиция
`crm-schedule-views.js` (кандидат из CLAUDE.md) в этот план не входит

**4. Общий контракт?** Да - `client_source` + `clientIsNew` читают публичный сайт,
crm-owner, crm-admin, crm-master. Поэтому фаза 1 (контракт, тесты зелёные) идёт до
любого фронтенда - Shared-Contract-First

## Как определяется источник

Приоритет, первый сработавший выигрывает:
1. `utm_source` в адресе (`?utm_source=yandex_maps`, `?utm_source=2gis`) - точное значение,
   требует, чтобы ссылка с меткой стояла в карточке организации. Внешний шаг за Владом
2. `document.referrer` - домен, который нас открыл (`yandex.ru/maps`, `2gis.ru`,
   `instagram.com`, `t.me`, `vk.com`). Из мобильных приложений карт referrer часто пуст -
   метод честно молчит, а не гадает
3. Ничего не сработало - `null`, поле остаётся пустым, админ проставляет руками в CRM

Первое касание запоминается в `localStorage` (`alikhan_client_source`): человек может
уйти на другую страницу сайта и вернуться, а UTM останется только в первом адресе.

Словарь источников - один на весь проект (`assets/client-source.js`), ключ в базе,
подпись на экране: `yandex_maps` → «Яндекс Карты», `2gis` → «2ГИС», `instagram`,
`telegram`, `vk`, `referral` («по рекомендации»), `walkin` («зашёл мимо»), `other`.

## Кто новый клиент

`clientIsNew` = у этой брони есть `client_id`, и она - самая ранняя не отменённая бронь
этого клиента (`ORDER BY date, start_time, created_at`). Отменённая бронь визитом не
считается - человек не приходил. Walk-in без телефона (`client_id` = null) метки не
получает вовсе: такие визиты по решению Алихана намеренно не связываются между собой,
и утверждать «новый» о них нельзя.

## Риски

- Раскрытая карточка перекрывает соседние записи - это осознанно: высота карточки равна
  реальной длительности (Задача G, Окно 53), сдвигать соседей нельзя. Раскрытие идёт
  поверх (z-index), закрывается повторным кликом
- Клик по кнопке раскрытия не должен открывать форму записи - `stopPropagation`
- `clientIsNew` считается доп. запросом на выборку броней (один запрос на список, не N+1)
- Публичная запись с сайта - боевой поток. Источник добавляется как необязательное поле:
  сервер принимает бронь и без него, старые открытые вкладки продолжают работать
