Составлено 24.08.2026 по итогам Фаз 1-5. Выполняется **только по явной команде Влада**.

## До начала

- [ ] Алихан предупреждён о коротком простое (решение Влада: предупреждение заранее, отдельно перед фазой не переспрашиваем)
- [ ] Снят дамп боевой базы: `pg_dump` с параметрами из `~/Desktop/alikhan-crm-api.env`, файл лежит локально
- [ ] Дамп поднят на локальной копии, на ней прогнано: `node tools/verify-2026-08-24-tenant-schema.mjs` и `node tools/verify-2026-08-24-tenant-cabinets.mjs`
- [ ] Счётчики строк по 20 таблицам до и после миграции совпали
- [ ] Записан коммит, на который откатываемся: `git rev-parse HEAD` **до** деплоя

## Проверка, без которой замок может оказаться бутафорским

На боевой базе выполнить:

```sql
SELECT rolsuper, rolbypassrls FROM pg_roles WHERE rolname = current_user;
```

Оба значения обязаны быть `false`. Если хоть одно `true` - **замок на этой базе не действует**, и миграция 058 сознательно остановит запуск сервера. Тогда переключение откладывается до заведения обычной роли-владельца.

Проверить это заранее из песочницы не удалось: классификатор блокирует соединение с боевой базой.

## Переключение

1. Скопировать в клон Amvera: `server.mjs`, `lib/`, `routes/`, `migrations/` (контур бэкенда), запушить в `master`
2. Дождаться старта: `GET /health` отвечает `{"ok":true}`
3. Сразу проверить живьём вход в три кабинета Алихана (владелец, администратор, мастер)
4. Проверить, что запись создаётся и видна после обновления страницы
5. Смотреть логи 10 минут: ни `row-level security`, ни `tenant_context_missing`, ни `unknown_tenant` быть не должно

Фронтенд (GitHub Pages) в этом Этапе не меняется - деплоить его не нужно.

## Если что-то пошло не так

Порядок обязателен - **сначала код, потом база**:

1. Откатить бэкенд на записанный коммит, дождаться живого `/health`
2. Выполнить `tools/rollback/multitenancy-etap-a-rollback.sql`

Обратный порядок не работает: новый код без арендатора в базе падает на каждом запросе - это его сознательное поведение.

Откат схемы возможен, **пока арендатор один**. После подключения Карины откатывают только код, схему оставляют как есть - старый код с колонкой `tenant_id` работает, у неё есть умолчание.

Путь отката проверен на живой базе: `node tools/verify-2026-08-24-tenant-rollback.mjs` (накат → откат → повторный накат, схема совпадает посимвольно, строки целы).
